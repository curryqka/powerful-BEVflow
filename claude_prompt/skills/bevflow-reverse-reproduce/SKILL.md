# 触发条件

用户说"开始第六阶段"，并给出旧项目代码路径，才执行。此前只做总控提示词 P5 里的准备清单。

# 基线现状

- PriorMotion 与 LEGO-Motion 没有现成权重。只能靠复现，再训练。
- BE-STI 没有官方代码。默认只引论文数字，不复现。我要求时再做。
- 旧代码是我自己写的，可以直接读，直接移植模块，不必重写。

# 一、盘点

1. 读旧代码，写 `docs/design/reproduce_<name>.md`：模块清单，输入输出，损失项，训练调度，额外的数据产物。
2. 列出与 MotionNet 管线的差异：输入表示，额外的预处理产物，评测协议。
3. 我的旧管线与现在的 MotionNet 管线可能不同。列出差别，问我用哪套作为统一口径。选定后，所有基线按同数据，同 split，同指标实现评测。
4. 问我旧项目里还留着什么：训练日志，中间 ckpt，论文里的报告数字。这些是最直接的对照。

背景信息，来自项目笔记，以旧代码实际内容为准：

- PriorMotion：VAE 加 KL 先验损失，SGRU 自回归解码，动静双分支。训练期解码器消费先验编码的隐变量，推理从学生分支采样。两个编码器权重不共享。
- LEGO-Motion：STPN 主干，实例 query 在线提取，双向注入，匈牙利匹配损失，两阶段损失调度。

# 二、数据

额外的预处理产物，生成到新版本目录 `$DATA/preprocessed/<data_version>_<name>`，写新的数据卡。不修改 `motionnet_v1`。

# 三、逐模块移植

顺序：共享主干，输出头，损失，训练调度。每个模块移植完，做一次前向形状与数值的合理性检查，再做下一个。

# 四、训练复现与对照

1. 先短训练，确认损失下降，各分支都有梯度。
2. 按项目预算完整训练：45 个 epoch，单卡 bs4，或 bs2 加梯度累积 2。保存最后 10 个 epoch 的 ckpt。
3. 用我们的评测器评测，和下面的对照项比：

| 对照项 | 参考值，来自项目笔记 |
|---|---|
| MotionNet 参数量与延迟 | 7.9M，19 ms |
| LEGO-Motion STPN 参数量与延迟 | 8.1M，21 ms |
| PriorMotion 参数量与延迟 | 11.5M，69 ms，其中体素化 12 ms，前向 57 ms |
| 三档 EPE | 我旧论文里的报告值，向我要 |

参数量应当基本一致，延迟在同量级。EPE 对不上时，先查数据管线与评测口径，再查模块。结果如实写进报告，不要为了对齐而调参。

4. 旧项目里若还有 ckpt，直接加载到新模型，同一输入对比输出。这是最强的等价验证，有就做，没有就靠训练复现。

# 五、为后续实验预留的接口

对应项目方案里最先要做的两个实验，现在加好成本很低。

**PriorMotion 侧**

- 隐变量来源开关：`latent_source` 取 `student` 或 `teacher`，teacher 用真值先验编码。用来做置换测试。
- 采样次数 K：一次前向返回 K 个样本。用来算 best-of-K 与 K 样本方差。
- 评测器支持按速度分箱输出。

**评测器侧**

- 可选开关：用 GT 静态掩码做完美门控，去掉后处理，扫描背景权重。
- 近邻 ckpt 权重平均的评测入口。
- 指标注册位：static P95，K 样本方差，best-of-K。

这些只是接口。实验本身在方案的第一周计划里另行安排。
