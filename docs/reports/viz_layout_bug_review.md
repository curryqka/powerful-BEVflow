# 可视化张量布局 bug 复盘与存量修复记录(2026-10-18)

> 性质:bug 复盘 + 可泛化经验。修复 commit `8c3b231`(10-18 19:12);本文另记录全部存量可视化的重生成。

## 一、症状与根因

- **症状**:quiver 图预测面板出现"乱码巨箭头"(官方权重在 test 上 fast@1.0s=1.011 的模型不可能画出这种场);由用户**肉眼**发现 —— 数值冒烟检查拦不住这类错
- **根因**:模型输出为 `(B*F, 2, h, w)`(channel-first,通道=位移分量),可视化移植代码误读为 channel-last —— 帧维与通道维错位,画出来的是同一块内存的乱码重排
- **正确约定**(以 `third_party/MotionNet/plots.py` 为准):`transpose → (F, h, w, 2)`,再沿帧维 `cumsum`(位移场是逐帧增量,累计才是绝对位移)

## 二、影响面界定(重要:指标无恙)

| 路径 | 布局约定 | 是否受影响 |
|---|---|---|
| 评测器(eval.py 系) | `view(B,-1,2,h,w)` ✓ 本就正确 | **不受影响,全部 EPE/OA/MCA 数字有效** |
| 训练路径 | 本就正确 | 不受影响 |
| 可视化(viz.py / viz_smoke.py) | 误读 channel-last ✗ | 受影响(已修) |
| 塌缩调查探针脚本 | 同一错误布局函数 | **结论不受影响**:对 R1A/R1B 使用同一错误布局,系统性偏差两边相同,30 倍量级差异是真实的 |

## 三、修复与防再犯(commit `8c3b231`)

1. `bevflow/evaluators/viz.py` 与 `scripts/viz_smoke.py` 改用 plots.py 同款解析(transpose → (F,h,w,2) + 帧维 cumsum)
2. **幅值 sanity 断言**:预测均值超过 GT 3 倍 + 0.5m 即报错 —— 布局类错误属于"数值冒烟拦不住、肉眼才拦得住"的类别,断言把这类错自动化(本次是肉眼拦住的,下次让断言拦)

## 四、经验(可泛化)

1. **张量布局约定必须在模块边界写明**(N,C,H,W vs N,H,W,C),eval 与 viz 两条路径对同一张量的解析应有单测对拍 —— 本次正是两条路径约定不一致、且仅可视化路径无数值校验,才漏网
2. **可视化是"人肉验收"路径,最缺自动检查**:幅值/分布类 sanity 断言应内建在生成函数里,而不是依赖看图
3. **布局争议以参考实现为仲裁**:`third_party/MotionNet/plots.py` 是上游权威写法,移植时先对拍再自写
