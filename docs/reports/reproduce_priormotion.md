## 4. 排查记录（时间序）

1. **后验塌缩（KL→0）**：两个种子的 KL 从 e1 的 0.2 单调降至 3e-5，隐变量被忽略，模型退化为"确定性自回归解码器"。这是旧配方（kld 0.5 恒定、无退火）的固有行为，非实现错误——论文数字很可能同样是塌缩态产物（EPE/分类仍优秀）。对策探索见第 5 节。
2. **BN 统计量瞬时污染**：s0 的 val 在 e8/e12 出现爆炸（fast 374/1.97），探针证实权重与 train 态正常、eval 态在污染窗口内失效，约半 epoch 自愈；由个别坏 batch 毒化 running stats。影响：s0 的 slow 指标偏高风险。未改训练配方（忠实复现优先）。
3. **两次 DSW 实例停止**：e29 与训练中断（latest.pt 保险把损失压到 ~4 分钟）；看守脚本 + 定期 ckpt 已固化。
4. **评测链两处工程 bug**：loader 未做模型分发、eval.py 残留旧 wrapper——已修复（commit 记录）。

## 5. kld 探索（用户批准的探索项 2）——结论：单靠 kld 权重无法防塌缩

变体 kld_weight=1.0（20261020_PM_kld1_s0）与 2.0（20261020_PM_kld2_s0），与忠实基线 0.5 对照。0.1 因方向必然更塌缩而跳过（记录于配置注释）。

**KL 轨迹（决定性证据）**：两个变体的 KL 都从 e1 的 **128** 在 6 个 epoch 内崩到 3-4e-5（kld1: e6 3.6e-5 → e44 3.3e-6；kld2: e6 4.2e-5 → e44 1.1e-6）。**权重从 0.5 提到 2.0（4 倍）也无法阻止后验塌缩**——隐变量在训练早期就被网络放弃，生成分支退化为确定性解码器。EPE 不受损（e40 val：kld1 0.0205/0.1544/0.5410；kld2 0.0175/0.1447/0.5156，与基线同级）。

**终评（test，bs1，2026-10-23）**：

| 项 | kld=1.0 | kld=2.0 | 忠实基线 s1（对照） |
|---|---|---|---|
| static | 0.1023（含坏 ckpt） | 0.0166 | 0.0168 |
| slow@1.0s | 5.5833（坏 ckpt） | 0.2347 | 0.2351 |
| fast@1.0s | 7.0000（坏 ckpt） | **0.9034** | 0.9150 |
| OA / MCA | 0.948 / 0.757 | 0.957 / 0.735 | 0.957 / 0.735 |
| last-10 fast | 3.42±8.22（训练后期不稳） | 0.516±0.004 | 0.524±0.007 |

- kld=2.0：精度与基线持平或略优（fast@1.0s 0.9034 vs 0.9150），但 KL 仍塌缩至 1e-6——**权重加 4 倍只延缓、未阻止后验塌缩**。
- kld=1.0：训练后期出现剧烈的 BN 统计量扰动（last-10 的 std ±8.2，epoch_45 正落在坏窗口内），终评不可用；这是与 s0 同源但更严重的稳定性问题，记录在案。

**结论**：此配方下后验塌缩是结构性的，单纯加 kld 权重无效。若要保住生成性（论文的立身之本），需要 KL 退火（β-VAE warm-up）、free-bits（每维 KL 下限）或 skip-connection 先验等结构性改动——属方法探索，超出忠实复现范围，记入 ideas 待用户决策。**论文数字本身是在塌缩态下取得的**，这解释了为什么 PriorMotion 的 EPE 提升有限（~15% fast）而主要收益来自其他机制。
